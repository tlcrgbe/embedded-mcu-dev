# 嵌入式 C 工程编码

版本：V1.2

## 1. 实现范围与职责

先读当前模块与邻近调用，沿用项目的工具链、接口和局部风格，面向已知硬件和明确调用关系实现。普通局部修改不扩大成架构重构；共享状态、公共接口或 CBB 的实质变化按当前已授权的设计执行。风格调整保持既有初始化、采样、校正、重试、返回点与结果发布行为。

实现前，先查找所属模块和项目内已有的能力，再考虑平台提供的接口；确认现有能力不满足后，才新增实现。复用须符合语义、调用上下文和资源约束，不为复用绕过职责边界。

最小修改应完整覆盖本次行为变化。接口、返回值或状态语义变化时，追踪相关调用方、配置与验证入口，在负责该规则的位置修复；不为缩小 diff 遗留不一致。

同一职责的数据和处理集中组织，只暴露必要接口，模块间优先具名直接调用。不同变化原因的规则分开组织：传输解析负责组帧与完整性，命令处理负责语义，业务负责状态与设备动作。规模小时可在一个命令模块解释命令并执行简单业务，但不把具体业务状态塞进接收解析器。已有边界按实际契约处理，不为套固定层数重构。

主流程应能看出输入、处理、状态更新和动作顺序。文件内私有函数即可表达的职责不强制拆文件，独立维护或复用时再拆模块。按职责和可读性拆函数；集中维护状态与硬件动作、统一故障处理的短函数有意义，几行直接可读的转换或无边界含义的转发不必包装。

引入上下文、回调注册、ops 表、调度框架或额外分层时，简短说明当前问题，各机制独立选择；简单实现无需逐项证明为何不用它们。保留已有且确有用途的移植、测试、诊断和兼容接口。

## 2. 接口与状态归属

| 方面 | 默认选择 |
| --- | --- |
| 标量、枚举 | 按值传递，直接返回结果 |
| 缓冲区、较大对象、输出参数 | 按需要使用指针，明确长度与存储期；局部元素指针可简化访问，异步操作不得保存失效栈地址 |
| 固定单实例 | 允许文件内 static 状态；真实多实例、重入或注入需求再用具名上下文 |
| 设备依赖 | 复用已有 Port/BSP 与具名接口，适配细节留在所属边界 |
| 失败结果 | 在本层按既有策略处理，或返回调用者需要的状态；没有失败语义可用 void |

输入处理产生事件或测量结果，业务维护自己的计数、告警、滞回与动作状态。一次性返回事件不为展示接口再增加缓存查询；持续测量值、滤波历史和状态按采样、控制与读取周期保留必要缓存。跨模块使用已有业务接口，不为追求封装自动新增 getter/setter 或重写算法。

初始化按依赖顺序安排，固定配置可用 static const，不机械增加 ready、initialized 等标志。简单标志够用时保持简单；互斥工况和明确转移适合枚举与 switch，不拆成多个交叉布尔标志。内部函数和数据优先 static，只读数据按用途使用 const，临时变量不因此改为 static。

## 3. 通过设计保证正确性

只核对本次改动涉及的约束，优先通过合适的数据表示、归属和执行顺序使内部调用成立，不默认增加运行时检查或单独设计报告。编译期可确定的尺寸、偏移、容量和对齐关系，优先通过类型、常量表达式或必要的静态断言保证，不在固定调用路径中反复检查。

| 涉及内容 | 实现前确定的约束 |
| --- | --- |
| 数值与时间 | 明确单位和有效范围，据此选择中间运算与结果类型，核对整数提升、符号/窄化转换及移位范围；时间差与计数方案适配回绕和实际调用间隔 |
| 缓冲区与资源 | 按最大有效数据量确定容量和长度关系，沿用项目内存策略，优先静态、有界资源；新增较大栈对象或耗时操作时核对实际影响 |
| 任务、ISR 或 DMA 共享数据 | 明确所有者、读写上下文、存储期和一致性要求，沿用平台适用的交接或同步机制；单实例不代表无并发，无共享不加锁 |
| 设备与执行时序 | 沿用已确认的初始化和访问顺序；单次设备等待与重试按实际需要设定超时，ISR 不阻塞，RTOS API 适用于调用上下文；常驻任务循环属于正常结构 |

涉及报文到数据的映射时明确字节序与对齐，避免依赖未经确认的内存布局。volatile 用于平台需要的寄存器和特定异步标志，不替代锁、原子性或 DMA 缓存一致性。设计无法消除的外部输入与运行故障按下一节处理。

## 4. 边界检查与故障处理

内部固定调用链遵循已确认约定，不逐层追加判空、范围、初始化检查或 assert，也不因接口公开就全面防御。同一条件在入口处理后不重复检查；数据或访问条件变化时再处理对应风险。已校验且未变化、未失效的数据直接交付和使用，避免丢弃已有结果后重复读取或计算校验；必要的快照与所有权交接仍保留。

协议与外部配置在负责的入口检查长度、容量和取值。帧完整、命令合法、设备允许动作是不同条件；运行状态会变化时保留执行点检查。需要整体拒绝的命令或配置，先完成必要校验再更新业务状态。

总线超时、通信失败和设备故障按项目既有策略处理，在适当层完成恢复、重试与记录，避免逐层重复。上层需要知道成败时保留结果，不因无需区分原因而改成 void；不新增通用错误框架。

assert 仅按项目需要表达关键内部不变量，不替代运行故障处理。断言内不放必须执行的副作用；示例和测试也先执行动作，再断言结果。

## 5. 代码表达

函数命名和复用以职责与契约为依据，底层比较或位值相同不代表语义相同。批量扫描与存储访问按平台支持的粒度、对齐和实际数据需求组织，避免无必要的整块复制与重复遍历；不为减少复制破坏一致性或绕过必要的设备访问边界。

项目已有规范优先。没有约定的新 C 代码使用 4 空格缩进、单行不超过 120 字符、PascalCase 类型、小写下划线函数与变量。普通声明不做大段列对齐；相邻宏定义的替换内容和简短行后注释按下述规则适度对齐。不批量重排无关旧代码，不应用 C++ 专用规则。

业务数值默认具名宏；已有 const 或枚举约定则延续，不重复定义。表达式宏替换体与参数加必要括号，避免带副作用实参重复求值。类型按位宽、ABI、索引和供应商接口需要选择，不全面禁止 int、size_t。单位与必要转换集中表达，不重复强转。

同一小组相邻宏定义的替换内容起始列适度对齐，宏名与替换内容之间至少留两个空格。按用途分组，不追求全文件统一列宽；过长宏单独处理，不为对齐扩展行宽或重排无关宏。

头文件沿用项目保护方式，自行包含声明所需类型。公共头文件声明本模块接口，外部依赖从所属模块头文件引入；缺失时提供最小依赖头文件，不把板级接口混入业务公共头，也不因此增加适配框架。

注释与新增诊断日志使用简体中文，功能要求固定的协议、解析字段和供应商文本保留。新代码适当增加注释，让维护者能从代码本身理解用途、状态含义和关键处理约定，不只依赖外部说明文档。不规定注释比例，不逐句翻译赋值、循环和明显条件。

模块主要入口和对外接口用简短注释说明用途，以及相关的调用时机、输入输出约定或失败后的行为；已有头文件说明的契约不在实现处重复整段。私有函数的职责不直观时补一句说明，小而清楚的函数不套长模板。重要状态、缓存和数据字段按需说明单位、有效条件、归属或更新时机，可在同一组声明前集中说明，不要求每个临时变量都有注释。

关键处理阶段与分支补充业务含义或原因，例如等待与重试、超时优先级、状态转移、失败保留结果、完整数据提交，以及特殊换算、字节序和硬件时序。注释放在对应代码附近，说明为什么这样处理、会保留或改变什么；能从名称直接看出的普通操作不重复解释。

允许用 // 写简短行后注释，适合字段单位、状态含义和局部特殊操作。代码与注释之间至少留两个空格；同一小组相邻代码的行后注释适度对齐，总行宽仍不超过 120 字符。按空行或职责分组，不跨函数、分支或整个文件统一列宽；遇到个别过长的代码或解释，另起一组或将解释移到代码前，不为对齐留下大片空白。项目工具链或已有风格另有要求时沿用项目约定。示例：

```c
#define DEVICE_PAGE_COUNT         3U
#define DEVICE_PAGE_BYTES         4U
#define DEVICE_RETRY_INTERVAL_MS  10U

uint32_t sample_ms;   // 本次有效采样的时间戳，单位 ms
uint8_t retry_count;  // 当前事务的连续失败次数，成功后清零
```

日志复用项目后端，格式匹配实参，满足上下文的阻塞与频率限制；保留当前任务要求的验收和临时诊断输出。

## 6. 自查与验证

自查主流程是否直接、职责与状态归属是否清楚、机制是否有实际用途，以及本次涉及的数据、时序和故障约束是否满足。可用变化核对边界，例如只改告警门限不应牵动底层采集；契约确有变化时按实际依赖处理。不按文件数、行数、NULL 或回调数量评价质量。沿本次关键路径核对检查、复制、遍历与状态分派的必要性；有重要取舍时说明具体依据，不逐函数填写检查表，也不以测试通过代替实现合理性审查。

同时检查主要接口、重要状态和关键处理是否有足够注释，是否与当前实现一致；避免只有代码复述、失效说明或重复模板。修改行为时同步更新相关注释，不为增加注释重排无关旧代码。

评审问题应说明具体触发条件、错误行为和影响，并核对源码及调用关系。无法确认的硬件或时序条件列为待验证项，不直接认定为缺陷。

按修改风险完成必要的检查、编译或针对性测试，不为排版写镜像测试。交付时区分静态审阅、主机测试、目标构建与板上验证，未执行项如实说明。此 skill 不替代算法设计或硬件验证，也不自动授权烧录或改变业务行为。

需要校准模块边界、缓存或抽象取舍时，按需读取[开源风格基准](references/open-source-style.md)对应条目。采用固定版本源码证据，项目约定优先，不照搬参考工程的全局状态或兼容框架，不要求每次编码联网或加载全部源码。
